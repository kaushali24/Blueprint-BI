# AI-Assisted Development Evidence

The ChatInsights MVP was built using a hybrid development methodology that heavily leveraged AI assistance alongside human review and deterministic testing.

## AI Tools Utilized

- **OpenSpec:** Used for specification-driven planning and architecting the foundational modules.
- **Coding/IDE AI Agent (Gemini/Antigravity):** Used directly in the IDE to write, refactor, and review application code.
- **Google Stitch:** Leveraged for rapid Next.js frontend prototyping and UI design iteration.
- **Gemini (Runtime):** Powers the core product features (Information Extraction, LangGraph Assistant).

## How AI Was Applied in the Development Lifecycle

1. **Repository Inspection & Auditing:** AI agents scanned existing directory structures and code to propose localized fixes.
2. **Implementation Plan Generation:** Before major refactors (like introducing Business Episode Extraction), AI drafted markdown plans for human approval.
3. **Code & Test Generation:** Boilerplate code, repetitive UI components, and exhaustive test cases (especially boundary conditions for ingestion) were generated by AI.
4. **UI Iteration:** Frontend alignment and visual design tweaks were iterated directly from Stitch prototype concepts and visual reviews.
5. **Debugging & Refactoring:** AI assisted in tracking down issues like `MultipleResultsFound` in customer resolution and atomic replacement rollback bugs.

## The Role of Human Validation

AI output was never blindly deployed. The development process required constant human-in-the-loop validation:

- **Dependency Audits:** When an AI agent accidentally proposed removing or downgrading a required package, it was caught in human review and reverted.
- **Architecture Correction:** Initial AI extraction was too fragmented. Human review noted this limitation, prompting a redesign to the "Business Episode" extraction model to consolidate orders correctly.
- **Semantic Bug Fixes:** The AI initially classified unconfirmed quotes (like the Rs. 4,500 quote for Kavindu) as Confirmed Revenue. Human testing identified the business logic error, leading to a prompt and schema adjustment to strictly enforce pending/confirmed semantics.
- **Build Quality Gates:** All AI-generated frontend code was subjected to strict TypeScript (`tsc --noEmit`), linting, and production build checks before merging.
